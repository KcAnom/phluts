# phluts

## Runtime framework (`packages/phluts`)

**1. `networkRequest` throws an unhandled async `StateError` that escapes the framework try/catch — HIGH**
`packages/phluts/lib/src/parsers/actions/phluts_network_request/phluts_network_request_parser.dart:33` — `model.results.firstWhere(...)` with no `orElse`. `results` defaults to `const []`, and `PhlutsService.onCallFromJson` (`phluts_service.dart:324`) is `FutureOr` but **not** `async` — it returns the Future unawaited at line 363, so the throw lands after the try/catch has returned. Reaches the zone handler: red screen in debug, crash reporter in release.
Verified stronger than reported: a request with `results` **omitted** and an HTTP **200** also throws — this is not an error-path-only bug.
Repro: `cd /Users/kcdacre8tor/phluts/packages/phluts && flutter test test/audit_repro_test.dart --plain-name F5 --reporter=expanded` → `escaped the framework try/catch: Bad state: No element`
Fix: `final result = model.results.where((e) => e.statusCode == response?.statusCode).firstOrNull; if (result == null) { Log.w(...); return null; }` — and make `onCallFromJson` `async`/`await` the parser so its try/catch actually covers async action failures.

**2. `request()` wipes headers and contentType on the caller-supplied Dio — HIGH**
`packages/phluts/lib/src/services/phluts_network_service.dart:20-21` — `_dio.options.headers = headers;` assigns (not merges) onto the shared `BaseOptions`. `Dio(BaseOptions(headers: {'Authorization': 'Bearer secret'}))` → header neither sent nor still present afterwards. Concurrent requests also race on each other's headers.
Repro: `flutter test test/audit_repro_test.dart --plain-name F7` → `sent headers: {}` / `dio.options.headers after call: {}`
Fix: build `Options(headers: request.headers, contentType: request.contentType)` per call and pass it to `_dio.get/post/put/delete(..., options: options)`. Dio merges over BaseOptions.
(Note: the claim that `BaseOptions` auth is "the documented way" is unsupported — grep over `docs/` finds no such example. Defect stands regardless.)

**3. The `setValue` recursion guard only works at the root — HIGH**
`packages/phluts/lib/src/framework/phluts_service.dart:237` — the guard skips resolution only when the handed-in node *is* `setValue`, but `resolveVariablesInJson` recurses the whole subtree, so a nested `setValue`'s child is substituted before `initState` writes the new values. `_SetValueWidget.build` then re-resolves an already-substituted string: no-op.
Aggravator: `docs/widgets/set_value.mdx` nests `setValue` under `scaffold > body` — the documented shape is the broken one. A root-level `setValue` does render `FRESH`, confirming the guard works only where it doesn't matter.
Repro: `flutter test test/audit_repro_test.dart --plain-name F11` → `registry x = FRESH` / `rendered = "STALE"`
Fix: make `resolveVariablesInJson` stop descending at any node whose `type == WidgetType.setValue.name`. The commented-out block at `variable_resolver.dart:12-16` was an attempt at exactly this.

**4. Non-Map POST bodies are silently replaced with `{}` — HIGH**
`packages/phluts/lib/src/services/phluts_network_service.dart:73` — `_updateBody` starts `Map bodyMap = {}`, fills it only `if (body is Map)`, returns it unconditionally. `PhlutsNetworkRequest.body`'s dartdoc reads verbatim "Can be a map, list, string, or bytes depending on encoder." Only POST calls `_updateBody`; GET/PUT/DELETE pass `request.body` through — same payload, different behavior per verb.
Repro: `flutter test test/audit_repro_test.dart --plain-name F6` → `POST list body arrived as: {}` for `body: [1,2,3]`
Fix: `if (body is! Map) return body;` at the top of `_updateBody`.

**5. `ExpressionResolver` routes any quoted expression to string concatenation — MEDIUM**
`packages/phluts/lib/src/utils/expression_resolver.dart:26` — the quote check sits above the comparison-operator check at line 31, so `'admin' == 'admin'` returns the String `admin' == 'admin`. `_evaluateBooleanExpression`'s `==`/`!=` branches are unreachable for any quoted input; the SDUI idiom `"'{{role}}' == 'admin'"` can never be true. Boundary confirmed: unquoted `admin == admin` and `5 > 3` return real bools.
Repro: `flutter test test/audit_repro_test.dart --plain-name F4`
Fix: test for comparison/logical operators before the quote check; teach `_parseExpression` to recognise quoted string literals.

**6. `PhlutsConditional` implicit-casts a `dynamic` to `bool` — MEDIUM**
`packages/phluts/lib/src/parsers/widgets/phluts_conditional/phluts_conditional_parser.dart:19-20` — `if (result)` where `evaluate` returns `dynamic`. Throws on a quoted comparison (finding 5's fallout) and on any `{{var}}` that is not yet set. Contained by `PhlutsService.fromJson`'s try/catch, so release builds render a blank area (`_showErrorWidgets && kDebugMode`, `phluts_service.dart:253`).
Repro: `flutter test test/audit_repro_test.dart --plain-name F4b`
Fix: `if (result == true)` plus a warning log when `result` is not a bool.

**7. Variable substitution stringifies every value — MEDIUM**
`packages/phluts/lib/src/utils/variable_resolver.dart:9` — always writes `value.toString()`. Since templating requires writing the field as a string, `"maxLines": "{{n}}"` with int `2` yields the String `'2'`, and generated `fromJson` throws: 36 × `(json['x'] as num?)?.toInt()` and 205 × `as bool?` in phluts_core (counts re-measured). `PhlutsDouble._fromJson` explicitly accepts `String`, so doubles work and ints/bools don't — an inconsistency, not just an unsupported feature. Release builds return null (subtree vanishes).
Repro: `flutter test test/audit_repro_test.dart --plain-name F2`
Fix: when the whole string is one placeholder (`^\{\{[^}]+\}\}$`), return the registry value itself; keep `toString()` only for interpolation.

**8. Variable values are re-expanded on each nesting level — MEDIUM**
`packages/phluts/lib/src/utils/variable_resolver.dart:6` — the whole subtree is resolved once per `fromJson`, and each parser re-enters `fromJson` for children, so a node N levels deep is resolved N times. With `a='{{b}}'`, `b='SECRET'`, rendering `{container > text: '{{a}}'}` prints `SECRET`. (The "injection" framing requires a variable value that itself contains `{{...}}`; the double-expansion is demonstrated.)
Repro: `flutter test test/audit_repro_test.dart --plain-name F10`
Fix: resolve exactly once — resolve only the current node's own scalars and let children resolve themselves, or mark resolved subtrees.

**9. `setValue(key, null)` deletes the key and leaks `{{key}}` to the user — MEDIUM**
`packages/phluts/lib/src/framework/phluts_registry.dart:79-85` — null means remove, and `variable_resolver.dart:9` leaves `match.group(0)` verbatim when `getValue` returns null. Reachable straight from server JSON: rendering `{'type':'setValue','values':[{'key':'k','value':null}],'child':{'type':'text','data':'v=[{{k}}]'}}` prints `v=[{{k}}]` to the end user.
Repro: `flutter test test/audit_repro_test.dart --plain-name F3`
Fix: store null unconditionally (a separate `removeValue` already exists at line 87); substitute `''` for present-but-null and leave the placeholder only when the key is absent.

**10. A custom parser targeting a built-in type is silently dropped — MEDIUM**
`packages/phluts/lib/src/framework/phluts_registry.dart:21-29` returns `false` + `Log.w` on collision; `phluts_service.dart:193-194` calls `registerAll(_parsers, override)` and **discards the returned Future entirely** (not even awaited); `Phluts.initialize` returns `Future<void>`. The dartdoc says parsers "are merged with the built-in parsers" and `override` is "useful for testing" — so the only working escape hatch is documented as something else.
Repro: `flutter test test/audit_repro_test.dart --plain-name F1` → `register() returned: false`, `getParser("text") is now: PhlutsTextParser`
Fix: register user parsers with `override: true` by default, or collect failures in `registerAll` and surface them from `initialize`.

**11. `getFormValue` returns the literal string `"null"` — MEDIUM**
`packages/phluts/lib/src/parsers/actions/phluts_get_form_value/phluts_get_form_value_parser.dart:18` — null-aware on the scope but not on the map lookup. `phluts_network_service.dart:79` substitutes action results straight into POST bodies, so an untouched optional field is transmitted as the 4-char string `"null"`.
Repro: `flutter test test/audit_repro_test.dart --plain-name F9`
Fix: `...?.formData[model.id]?.toString();` and make the return type nullable.

**12. Five widget parsers and three action parsers are unreachable from the public barrel — LOW**
`packages/phluts/lib/src/parsers/widgets/widgets.dart:1` omits `app_bar`, `inkwell`, `row`, `text`, `tool_tip`; `actions.dart` omits `form_validate`, `get_form_value`, `network_request`. `phluts_service.dart:12-20` works around it with direct `src/` imports. (Corrections to the original count: `phluts_image_parser_io` **is** reachable via the conditional-export shim at `widgets.dart:44`, and `phluts_double` is a value class, not a parser. 5+3, not 7+3.)

## CLI (`packages/phluts_cli`)

**13. Duplicate `screenName` across files silently overwrites output while reporting success — HIGH**
`packages/phluts_cli/lib/src/services/build_service.dart:374` — the uniqueness guard tests the *file-local* `artifacts` list inside `_extractDslArtifacts`; `_processArtifacts:497-500` writes `<outputDir>/screens/<name>.json` with no cross-file registry (`generatedResults` is written at :501 and never read). Winner depends on `Directory.list` order → not reproducible across machines. The lost screen is reported as generated and the survivor goes to `deploy`.
Repro: two files in `<project>/phluts/` both `@PhlutsScreen(screenName: 'home_screen')` with distinct bodies, then `dart run packages/phluts_cli/bin/phluts_cli.dart build --project <project>` → logs `✓ Generated screen: home_screen.json` twice, `processed: 2, failed: 0`, and `find <project>/phluts/.build -type f` returns one file.

**14. `_extractJson` accepts the first JSON object anywhere on stdout — HIGH**
`packages/phluts_cli/lib/src/services/build_service.dart:699` — `output.indexOf('{')` returns the first balanced object, fed straight to `jsonDecode` at :545. `_createWrapperScript` (:458-471) emits a bare `print(jsonEncode(json))` with no sentinel, so any `print` of a JSON-shaped object in user screen code wins.

**15. `deploy` ignores the configured `outputDir` — MEDIUM**
`packages/phluts_cli/lib/src/services/deploy_service.dart:30` hardcodes `path.join(projectDir, 'phluts', '.build')` while `build_service.dart:30` honours `options.outputDir` (regex-parsed at :207-209). **16. Every compile error is misreported as "requires Flutter" — MEDIUM**
`packages/phluts_cli/lib/src/services/build_service.dart:666-672` — the heuristic list includes `'widgets/'`, and every phluts widget lives under `packages/phluts_core/lib/widgets/...`, so any diagnostic citing a phluts widget matches. A `Too many positional arguments` error in a screen with **no** Flutter import is replaced with "Replace `import 'package:phluts/phluts.dart'`…". The real error is only visible with `-v`.
Repro: `return PhlutsText('Hello');` (positional instead of `data:`) → the Flutter message; re-run with `-v` → `Error: Too many positional arguments: 0 allowed, but 1 found.`
Fix: restrict the heuristic to `package:flutter/`, `dart:ui`, `package:phluts/phluts.dart` (`_validateImports` already catches the import case up front), and always append the first real `Error:` lines.

**17. `phluts deploy` resolves the project from CWD while `build` walks up to the pubspec — LOW**

**18. `PhlutsOptions`' own documented `sourceDir`/`outputDir` values target the filesystem root — LOW**
`packages/phluts_core/lib/core/phluts_options.dart:23-24` declares `'/phluts/'` and `'/phluts/.build'` as defaults and as the doc example; `build_service.dart:30`/`:41` use `path.join`, which resets on an absolute component.
